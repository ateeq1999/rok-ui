# Migrating to 0.9

0.9 adds timed concurrency modes, an observer and hydrated state to blocs, retries, token
refresh and multipart uploads to the HTTP client, a mock server and `bloc_test!` for tests,
scoped context values, a forms panel in devtools, and `cargo rok-ui new --layout workspace`.
Hand-written blocs need one edit (`Debug`); code that matches on `Concurrency` needs two new
arms.

## Events and states are `Debug`

`Bloc::Event`, `Bloc::State` and `Cubit::State` must implement `Debug`, so a `BlocObserver`
can log them. Code generated by `cargo rok-ui generate` already derives it. For hand-written
blocs, add the derive:

```text
// Before
enum NotesEvent { NotesRequested }
#[derive(Clone, PartialEq)]
struct NotesState { .. }

// After
#[derive(Debug)]
enum NotesEvent { NotesRequested }
#[derive(Clone, Debug, PartialEq)]
struct NotesState { .. }
```

The compiler names each type that is missing it (`NotesEvent doesn't implement Debug`).

## `Concurrency` has two more variants

`Concurrency::Debounce(Duration)` and `Concurrency::Throttle(Duration)` are new. A `match` on
`Concurrency` in your code needs arms for them (most apps only construct the value, which
is unaffected).

## The HTTP client is its own crate

`rok_ui::http` now re-exports the `rok-ui-http` crate, which has no GPUI. Paths and types are
unchanged, so nothing needs editing. With the `http` feature, `rok_ui::runtime` is
`rok_ui_http::runtime`: still one shared runtime per app.
