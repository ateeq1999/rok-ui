# Migrating to 0.6

0.6 adds the data layer and router v2 next to the 0.5 APIs. Nothing is removed; one function
is deprecated.

## `db::use_query` is deprecated

Before:

```rust,ignore
#[component]
fn Users(window: &mut Window, cx: &mut App) -> impl IntoElement {
    let users = db::use_query("users", window, cx, |db| async move {
        User::query().all(&db).await
    });
    // users.data(), users.error(), users.is_loading()
}
```

After (enable the `query` feature, which `db` already does):

```rust,ignore
fn users_query() -> QueryOptions<Vec<User>> {
    db::db_query(query_key!["users"], |db| async move { User::query().all(&db).await })
}

#[component]
fn Users(cx: &mut Cx) -> impl IntoElement {
    let users = query::use_query(cx, users_query());
    // users.state(), users.data(), users.error(), users.is_loading()
}
```

- Readers of the same key now share one cached copy and one fetch.
- `db::invalidate("users", cx)` keeps working and also invalidates `query_key!["users", ..]`;
  in new code prefer `query::invalidate(cx, &query_key!["users"])`.
- Writes: `db::run` stays. `query::use_mutation(cx, db::db_mutation(..).invalidates(..))` adds
  pending and error state and optimistic updates.

`db::use_query` will be removed in 0.8.

## Components can take `cx: &mut Cx`

`#[component]` functions may take one `cx: &mut Cx` instead of `window: &mut Window` and
`cx: &mut App`. `Cx` dereferences to `App`, and `cx.window` is the window. Existing components
need no change.

## Router: typed routes and file-based routes

The 0.5 `Router` API is unchanged. To adopt typed routes, move each string route to a type:

1. Declare the route: `typed_route! { pub struct NoteRoute = "/notes/:id" { pub id: u64 } }`.
2. Replace `.route("/notes/:id", |route, _, _| NotePage::new(route.param_as::<u64>("id")..))`
   with `.route_to(|note: NoteRoute, _, _| NotePage::new(note.id))`.
3. Replace `Link::new(id, format!("/notes/{id}"))` with `Link::to(&NoteRoute { id })` and
   `router::navigate("/notes/3", cx)` with `router::navigate_to(&NoteRoute { id: 3 }, cx)`.
   The compiler now lists any call site with a wrong parameter.

To move to file-based routes (see the router guide and `examples/file_routes`):

1. Add `rok-ui-build` to `[build-dependencies]` and a `build.rs` calling
   `rok_ui_build::routes("src/routes").generate()`; add `rok_ui::routes!();` to `main.rs` or
   `lib.rs`.
2. Move each route into `src/routes/<path>.rs` with `file_route! { component: Page }`, turning
   `:id` into a `$id.rs` file name and `route.param_as` into `params: { id: u64 }` plus
   `params(cx)` in the page.
3. Move the app shell into `src/routes/__root.rs` as a layout (`layout: AppShell`, with
   `#[children]`).
4. Replace string links with the generated types (`routes::NotesId { id }`).
5. Load data with `QueryOptions` from a `features/` module and `Suspense` in the page.
